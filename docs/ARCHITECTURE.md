# Architecture (decided Fri 13 Nov, 16:45. Built for speed: deadline Sun 15 Nov 12:00)

## Stack

| Layer | Choice | Why |
|---|---|---|
| App | **Next.js (App Router) + TypeScript + Tailwind**, in `web/` | Moss ships fastest in it |
| Map | **MapLibre GL JS** | Smooth pan/zoom, layer toggles, GeoJSON route lines, animated markers. A clean 2D "mission control" look, deliberately different from Sol Atlas's 3D game HUD |
| Mars basemap | **OpenPlanetaryMap Mars tiles** (web-mercator raster, checked live 13 Nov): `https://cartocdn-gusc.global.ssl.fastly.net/opmbuilder/api/v1/map/named/opm-mars-basemap-v0-2/all/{z}/{x}/{y}.png`. Fallback hillshade: `https://s3.us-east-2.amazonaws.com/opmmarstiles/hillshade-tiles/{z}/{x}/{y}.png` | Whole-planet context for free. Our region's NASA layers sit on top |
| Region layers | Images baked by our data pipeline, added as MapLibre `image` sources with lon/lat corners | No tile server needed |
| Routing | `planner/` (pure JS, T-05), run in a **Web Worker** from the web app | 30 ms–1 s per route. The UI never freezes |
| AI explanation | Next.js route handler `web/app/api/explain/route.ts` → Claude API (Anthropic), key in `ANTHROPIC_API_KEY` | Server-side only. It gets **only computed numbers** and must not invent any |
| Space weather | Next.js route handler `web/app/api/space-weather/route.ts` (port of Sol Atlas's DONKI function), key in `NASA_API_KEY` (falls back to `DEMO_KEY`) | Live NASA data, answers challenge objective O6 |
| Deploy | **Vercel**, from `main`, root directory `web/` | Moss already uses it. Every push = live preview |

Mars on a web-mercator map: our region is small (tens of km), so the projection distortion is negligible. Distances are computed in the planner from the elevation grid's metre cell size, never from map pixels.

## The data contract (lets both people build in parallel)

The data pipeline writes, and the web app + planner read, **exactly** this:

```
web/public/data/<region-id>/
  meta.json      ← see below
  elev.i16       ← raw Int16 little-endian, metres, width×height, row 0 = NORTH
  slope.png      ← 8-bit grayscale, degrees × 4 (0–63.75°), same grid
  visible.jpg    ← colour/visible image covering the same bounds
  thermal.jpg    ← (optional) THEMIS night IR, same bounds
  pois.json      ← science points: [{ id, name, lon, lat, why, source }]
```

`meta.json`:
```json
{
  "id": "gale",
  "name": "Gale Crater",
  "lon": [137.0, 138.0],
  "lat": [-5.5, -4.5],
  "width": 1024,
  "height": 1024,
  "cellM": [57.8, 57.8],
  "elevRange": [-4500, 500],
  "sources": [{ "layer": "elev", "dataset": "…", "mission": "…", "url": "…" }]
}
```

Loading in the browser: `new Int16Array(await (await fetch(url)).arrayBuffer())`, then convert to `Float32Array` for the planner. Grid cell (x, y) ↔ lon/lat is linear inside the `lon`/`lat` bounds.

**Until real data lands:** Moss's side uses a synthetic region in the same format (`web/public/data/demo/`, generated by `planner/scripts/make-demo-region.mjs`). Swapping to the real region means changing one region id.

## Planner API (T-05 builds it, the web app calls it)

```js
import { planMission } from '../../planner/src/plan.js';   // pure ES module, works in a Web Worker
planMission({ elev, w, h, cellX, cellY, fineSlope, start: [x, y], end: [x, y], pois: [{ x, y, id }],
              sun /* optional { endMarginH } */, params /* optional EVA_DEFAULTS overrides */,
              roundTrip = true /* walk back to the airlock */, maxStops = 2 /* SCIENCE stops */ })
// → [{ strategy: 'SAFE'|'FAST'|'SCIENCE', path: [[x, y], …] | null, budget, verdict, poisVisited: [id], stops: [{ id, d }], ms }]
// budget = eva.js budget(): distance (m, whole EVA), oneWay (m), roundTrip, walkT, stopT, totalT (s), o2 (kg),
//          marginPct (O2 left at the airlock, %), gain, loss, maxSlope (deg), timeline [{ d, t, o2 }]
// verdict = eva.js verdict(): { lvl: 'go'|'caution'|'nogo', issues: [{ lvl, msg }] }
// path === null → no walkable route; verdict is NO-GO with a message. Out-of-grid start/end throws RangeError.
```
Strategies: **FAST** = least walking time · **SAFE** = least O₂ with a penalty that grows quadratically above 10° and a 15° routing limit · **SCIENCE** = least-O₂ legs through up to 2 POIs that add the least detour (≤ max(1 km, 50 % of the direct distance)), 20 min work at each stop. With `roundTrip` (default) A* minimises the cost of going *and* coming back, and the budget covers the whole out-and-back EVA.

## AI explanation contract

`POST /api/explain` with `{ region, routes: [{ strategy, distanceKm, durationMin, o2MarginPct, maxSlopeDeg, verdict, poisVisited: [names] }], daylight, spaceWeather }` → `{ recommended, text }`.
The system prompt says: use only the numbers given, recommend one route, keep it to 3 sentences, and mention the tradeoff. If the API fails, the UI shows a template sentence built from the same numbers, so the demo never breaks.
